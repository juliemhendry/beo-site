## 1. Research Scientists & Psychologists Panel

**Panel composition:**
- Dr Sarah Chen, Research Methods Specialist (UK)
- Prof Michael O'Brien, Psychology of Technology (US)
- Dr Priya Sharma, Digital Wellbeing Researcher (India)

### Strengths ✅

**Research credibility:**
- Multiple citations strengthen claims (Paulhus & Vazire, Andrews et al., Ellis et al.)
- Removes dependency on single unpublished thesis
- Acknowledges self-assessment as "well-documented challenge" - accurate framing
- Hypothesis clearly stated and testable

**Methodology transparency:**
- BPS ethics compliance explicitly stated
- Anonymous data collection well explained
- Timeline realistic (Feb launch → Easter findings)
- Doesn't overclaim or promise breakthrough results

**Scientific tone:**
- "Research shows..." not "Studies prove..."
- "Consistently find poor correlations" - appropriate hedging
- "We're testing whether..." - honest framing as hypothesis

### Concerns ⚠️

**Missing detail:**
- Sample size not mentioned (how many participants needed?)
- Power analysis? Statistical approach?
- How will "findings" be validated if anonymous?
- What's the control condition?

**Research claims:**
- "People can estimate frequency reasonably well, but struggle with duration" - needs citation
- Which specific addiction questionnaires "fail to correlate"? Be specific
- "Perception gap" - is this an established term in literature or your coinage?

**Ethics:**
- BPS Code reference is good, but what about informed consent process?
- How do users withdraw if data is anonymous?
- Who's the ethics approval authority? University? Independent?

### Recommendations 📋

1. **Add research protocol link** - "Read our full methodology" (even if brief)
2. **Specify sample size target** - "We aim to recruit 500+ participants globally"
3. **Define success metrics** - What would disprove your hypothesis?
4. **Citation style** - Consider adding DOIs or links to cited papers
5. **Preregistration** - Mention if study is preregistered (OSF, ClinicalTrials.gov)

**Overall verdict:** Credible, appropriately cautious, but needs more methodological transparency for academic audience.

## 2. Potential Users Panel

**Panel composition:**
- Emma, 24, Marketing Manager, London (heavy Instagram user)

**Jake's feedback:**

**Aisha's feedback:**
> "The 'reclaim real life' card resonated. It's not about 'phone bad' - it's about what I'm missing. That feels different."

### Confusion Points ❓

**Emma:**
- "What's BSMAS? Is that a questionnaire I take once or ongoing?"

- "How long does each intervention take? The '30 seconds' claim is gone now."

- "Do I need to share my actual screen time data with you? That feels private."

**What works:**
- Hero clear and compelling ("Your phone doesn't have to control you")
- Benefits cards visual and scannable
- Intervention categories intuitive (breathe, move, etc.)

**What doesn't:**
- Research Foundation section too text-heavy (Emma: "I skimmed this")

1. **Simplify research section** - Use more headings, less dense paragraphs
2. **Add FAQ section** - Answer common questions (frequency of notifications, time commitment, etc.)
3. **Show examples** - Screenshots of what an intervention looks like
4. **Add testimonials space** - Even "Coming Easter 2026" shows you're thinking about it
5. **Clarify social media scope** - Instagram, TikTok, Facebook, Twitter, Snapchat?

**Overall verdict:** Compelling message, needs simplification and visual examples. Users want to know *what they're signing up for* practically.

## 5. Technical & Security Review

**Panel composition:**
- Security Engineer
- Frontend Developer
- DevOps Engineer

### Technical Stack Assessment

**Current setup:**
- Static HTML/CSS (no JavaScript framework)
- GitHub Pages hosting
- Formspree for email (not configured yet)
- No build process

**Strengths ✅**
- ✅ Simple = secure (no server-side code to exploit)

- ✅ Easy to deploy (git push)
- ✅ Free hosting (GitHub Pages)
- ✅ HTTPS automatically via GitHub

**Weaknesses ⚠️**
- ⚠️ No CSP (Content Security Policy) headers
- ⚠️ No form validation beyond HTML5 `required`
- ⚠️ Formspree ID placeholder not replaced
- ⚠️ No analytics configured yet
- ⚠️ Base64 images in HTML (388KB team.html - huge!)

### Security Concerns

**Email handling 🔒**
- Formspree: Moderate security, but emails are plaintext
- No rate limiting on form submissions
- No CAPTCHA or bot protection
- Potential for spam/abuse

**Privacy claims vs reality:**
- **Claim:** "Truly anonymous, no device IDs"
- **Reality:** How does this work? The app collects data somehow
- **Question:** Is iPhone/Android device data truly anonymous?
- **Missing:** Link to technical privacy documentation

**External dependencies:**
- Formspree (third party)
- Google Analytics planned (third party)
- Any CDN usage? (Doesn't appear to be)

### Code Quality

**HTML validation:**
- Semantic HTML ✅
- No deprecated tags ✅
- Inline styles in some places ❌ (footer)
- Missing lang attribute checks

**CSS:**
- CSS variables used well ✅
- No vendor prefixes (might need for older browsers) ⚠️
- Media queries present ✅
- Could benefit from minification

**Accessibility:**
- Needs ARIA labels ❌
- No skip links ❌
- Focus indicators not specified ❌

### Performance

**File sizes:**
- index.html: 18KB ✅
- team.html: 388KB ❌ ← PROBLEM
- blog.html: 6.3KB ✅

**Why team.html is huge:**
- Base64 encoded images (2 photos = ~385KB of the file)
- Solution: Use actual image files (png/jpg), not base64

**Loading performance:**
- No image optimization
- No lazy loading
- No preconnect/prefetch hints

### Recommendations 📋

**Critical fixes:**

1. **Fix team.html size:**
   ```bash
   # Extract base64 images to actual files
   # mark-photo.png (~175KB)
   # julie-photo.png (~210KB)
   # Update team.html: <img src="mark-photo.png">
   ```

2. **Configure Formspree:**
   - Replace `YOUR_FORM_ID` placeholder
   - Set up autoresponder
   - Add honeypot field for spam protection

3. **Add security headers:**
   ```yaml
   # _config.yml or netlify.toml
   Content-Security-Policy: "default-src 'self'; ..."
   X-Frame-Options: DENY
   X-Content-Type-Options: nosniff
   ```

4. **Form validation:**
   ```html
   <input type="email" required pattern="[^@]+@[^@]+\.[^@]+">
   ```

**Recommended:**

5. **Add Google Analytics:**
   - GA4 setup
   - Track: pageviews, signups, blog reads, thesis clicks (if re-added)
   - GDPR/privacy note about analytics

6. **Image optimization:**
   - Convert photos to WebP
   - Add width/height attributes
   - Implement lazy loading

7. **Create _headers file** (if using Netlify) or equivalent:
   ```
   /*
     X-Frame-Options: DENY
     X-Content-Type-Options: nosniff
     Referrer-Policy: strict-origin-when-cross-origin
   ```

8. **Add robots.txt:**
   ```
   User-agent: *
   Allow: /
   Sitemap: https://beo.llc/sitemap.xml
   ```

9. **Create sitemap.xml:**
   - List all pages
   - Help with SEO

**Security best practices:**

10. **Document privacy technically:**
    - Create `/privacy-technical.html`
    - Explain exactly what data is collected, how, where stored
    - Link from privacy page

11. **Third-party audit:**
    - Before launch, have security firm review
    - Pen test the email form
    - Verify Formspree configuration

**Overall verdict:** Technically sound foundation, but several critical fixes needed before launch (team.html size, Formspree config). Security adequate for static site but needs headers and documentation.
